# StudyFlow Agile Redesign

Instead of planning and building the entire StudyFlow application before testing it, I would develop the application in smaller iterations. Each iteration would produce a small working part of the application that can be tested before moving on. Feedback and problems discovered during an iteration could then be used to adjust the plan for the next iteration.

## Iteration 1 - Study Boards

The first iteration would allow students to create and view their study boards, with each board representing a subject. Once this functionality is working, it would be tested and feedback would be collected before continuing development.

## Iteration 2 - Chapters

The second iteration would allow students to open a study board and add chapters to organise the subject. The plans for this iteration could also be adjusted based on feedback received during the first iteration.

Further features, such as topic cards and study progress tracking, would be developed in later iterations rather than building the entire application at once.
